DS Bar · 设置页重设计

与已批准的概览页同一套设计语言：近黑画布、单一强调色、细描边容器、字号跨级分层。 重点解决「凭据区域信息混乱、状态不可见、危险操作缺乏约束」三类问题。
先说清设置页现在的四个具体问题（都来自现有代码）：
  1. 凭据区把两件不同的事塞在一起：平台 userToken 与 API Key 都叫「凭据」，但前者解锁用量、后者解锁余额，混在一张卡里，用户不知道先填哪个、填了能多看到什么。
  2. 没有任何「测一下」的入口：粘贴 userToken 后只能回概览页下拉刷新才知道对不对，错了也只看到一个笼统的「用量不可用」。
  3. Key 列表只有名称和删除按钮：没有打码后的 key 尾号，无法核对是哪一把；删除是直接弹确认框，没有二次约束，误删就得重新粘贴。
  4. 「数据来源」三行是纯文本装饰：写着 platform.deepseek.com/api/v0/usage/*，但不能点、不告诉你现在通不通。

三 · 关键改动对照

问题现状做法新做法
不知道哪部分能用要回概览页看是否报错 设置页顶部「连接状态」两块：余额 / 用量，各自一个语义点 + 一句人话。
两件凭据混在一起同在一张「凭据」卡 拆成「平台会话（解锁用量）」与「API Key（解锁余额）」，标题右侧直接写明解锁什么。
填完不知道对不对无测试入口 「测试连接」弹层逐项列出：每个 Key 的状态码与余额、userToken 状态、导出是否跳过。
分不清哪个 Key只显示名称 列表行显示 sk-ab…9f2c 打码尾号 + 本月 token 量。
删除太容易误触行内垃圾桶 → 确认框 移到 Key 详情子页底部，确认框要求输入 key 尾 4 位。此项需新增原生方法支持打码回传。
刷新间隔靠拖23 刻度滑块 四档分段控件（15 分 / 30 分 / 1 时 / 6 时），点选即生效。
数据来源不能点纯文本三行 保留地址文本，但改用「官方 / 网页接口」徽章标注稳定性，并说明失效影响面。

四 · 落地前提（三项需要改原生层）

新增的三个能力

  • 打码 key 回传：现在 configJson() 的 keys 只含 id 与 name，ApiKeyEntry.masked 已实现但没输出。加一个字段即可，无风险。
  • 测试连接：新增 testConnection 通道方法，逐项返回 {target, ok, code, detail}。复用现有 DsHttp 与 DsRepository，不动取数逻辑。
  • 删除需输入尾号：属于纯 Dart 层交互，不需要原生改动。

不做的

  • 不做多账号切换：当前数据模型是单账号，加多账号要改快照结构与通知逻辑，属另一件事。
  • 不做凭据导出/导入：会让「只存本机」的承诺变模糊。
  • 不做「金额小数位」设置项：稿里画了但建议砍掉——缩位规则已在 Fmt 里统一，暴露成开关只会让各处显示不一致。请特别确认这一条。
  • 不做加密存储：当前用应用私有 SharedPreferences。加 EncryptedSharedPreferences 需引入 security-crypto，属可选项，本次不做。

五 · 请逐条确认

全勾＝按此稿改设置页。改动范围：settings_page.dart（重写为四段结构 + 两个子页）、 common.dart（自绘开关、分段控件、测试结果行）、 native_bridge.dart + MainActivity.kt + DsPrefs.kt（打码回传、testConnection）。 概览页与数据层不动。
